AGENT OFFICE
The idea

A harness for personal agents, with the fun of a game

  • You build the team. Name an agent, write what it does, give it a computer and the account passes it needs.
  • They live in a room. Each agent has a desk. They walk to the letterbox for mail, to the wall calendar for the diary, sit at the keys only when they use a computer.
  • It is a real harness underneath. Identity, memory of every chat, unattended jobs, approvals, budgets, evals.
  • Built on AWS end to end. Bedrock, AgentCore, Cognito, App Runner, DynamoDB, S3, EventBridge.

Architecture

Everything runs on AWS

Browser / TelegramPixel office UI, or a bot chat. Same agents, same history.
App RunnerUI server. Cognito sign-in, SigV4 proxy to the runtime, Telegram webhook, routine editor.
Amazon CognitoHosted sign-in. The user id is the Cognito subject, nothing else.
Bedrock AgentCore RuntimeStrands Agents TS SDK in an arm64 container. Attended turns stream SSE; jobs run detached.
Amazon BedrockClaude Haiku 4.5, Sonnet 4.6, Opus 4.6 - picked by the computer you give an agent.
AgentCore IdentityOAuth token vault for Gmail and Google Calendar. Scope-aware, per user.
AgentCore Code Interpreter + BrowserA sandboxed VM and a real browser per agent, only if its rig has them.
DynamoDB + S3Worlds, routines, usage counters, jobs. Chat snapshots and files in S3.
EventBridge SchedulerOne schedule per routine, invoking the runtime directly. No Lambda in between.

Identity

One person, several ways in

  • Amazon Cognito hosted sign-in. The server trusts the id token only; nothing the browser sends can change who you are.
  • Agents, chats and memory follow you to any browser.
  • Telegram becomes the same account with /link - one code, typed once.
  • AgentCore Identity keeps the Google tokens: the agent asks for consent once, the vault holds the refresh token, calendar and mail reuse the same provider with different scopes.

Connectors

Gmail and Calendar, with guard rails

Read and search mail

Real Gmail through the AgentCore token vault. The stub inbox works the same way with no account, so the whole flow demos offline.

Drafts only, never send

The agent prepares; the human sends. There is no send tool to misuse.

Calendar read and write

List the week, find free slots, create and update events. No delete tool - cancelling emails everyone.

Nobody is emailed by surprise

Invitations only go out when the user asked for them. The agent says whether anyone was told.

Passes are per agent

Grant Gmail to the scheduler, not to the writer. A pass to an unlinked account is dropped automatically.

Room fixtures

Link Gmail and a letterbox appears. Link Calendar and a wall calendar goes up. Agents walk to them.

Autonomy

Agents that act when not spoken to

  • Jobs run unattended. Start one from the browser, or let a routine start it. Every job is also a chat with its full transcript.
  • Routines on EventBridge Scheduler: "weekdays at 08:00", "every 30 minutes". Each is a real schedule that invokes the AgentCore runtime directly.
  • Triggers for mail and calendar poll cheaply and only wake the model when something is new.
  • Outbox: results and files land on Telegram. No Telegram? They wait in the JOBS tab.
AGENT OFFICE
Approvals

Nothing changes your world without a nod

  • In an unattended run, booking an event or leaving a draft pauses the agent with a Strands interrupt.
  • The paused state, tool call included, is snapshotted by the SDK session manager into S3.
  • Telegram asks: /approve job-… or /deny job-…. The browser has the same buttons.
  • On approve, the very same tool call completes. On deny, the agent finishes without it and says so.

Reliability

Rails on every agent

Long chats survive

Summarising conversation manager with proactive compression. The tenth long turn no longer dies on context overflow.

Throttles are patience, not errors

Retry strategy with exponential backoff, including Bedrock's pre-stream throttle that the default misses.

Every tool has a deadline

A hung page or VM comes back as an error the model can route around, not a frozen tab.

Metering and ENERGY

SDK metrics summed per user per day into DynamoDB. A token budget stops runaway routines; the ENERGY bar in the room is the real number.

Chat history by the SDK

Session snapshots in S3. Reopen a chat and the agent genuinely remembers.

20 scripted evals

Tools, refusals, mail, calendar, delegation, parallel fan-out. 20 of 20 passing on Haiku.

The tribe

Colleagues that start with a full head

  • Handoff envelopes. The boss fills a brief, the context it has, the deliverable and constraints. The envelope adds who the user is, the date and the house rules.
  • Parallel fan-out. Independent subtasks go out in one turn; the SDK runs them concurrently and the room animates every busy colleague.
  • Roles with skills. A researcher knows how to research before you type a word.
  • Four desks. Boss plus three colleagues, each with its own computer and passes.

AWS services

What carries the weight

Amazon Bedrock

Claude Haiku 4.5, Sonnet 4.6 and Opus 4.6 via the Strands BedrockModel, streaming, with extended thinking for the thought clouds.

AgentCore Runtime

The agent container. Session affinity, SSE streaming, detached jobs with a busy health check.

AgentCore Identity

Workload identity and OAuth2 token vault for Google, per user, per scope.

AgentCore Code Interpreter and Browser

Sandboxed Python for documents and data; a cloud browser whose frames paint onto the agent's monitor.

Cognito, App Runner, ECR

Sign-in, the public UI service, and the images for both services.

DynamoDB, S3, EventBridge Scheduler, CloudWatch

State, snapshots and files, the clock for routines, and the logs that explained every bug.
